# STEP 23 Checker v2.3: batch pair checker (usage and acceptance criteria)

Files:

- `scripts/step23_checker_v2_3.py`: the checker. Standard library only; imports no repository module; makes no network requests; read-only.
- `scripts/profiles/step23_2026-11-03_pr15_cutover.json`: expectations for exactly one BASE/NEW pair.
- `tests/test_step23_checker_v2_3.py`: 205 synthetic adversarial tests (383 subtests).

## Purpose

The checker compares two `fundamentals-batch-results` artifacts that share an evaluation date: BASE and NEW. Optionally, it also reads each run's `sec-companyfacts-raw` artifact. It checks:

- run integrity: cutoff, policy, operational review, provenance SHAs, snapshot hashes, raw file hashes
- DEC055 gate output, each run under its own policy: V1 relabels produced dependents only; V2 lists every dependent
- coverage, recomputed independently from the per-ticker files
- run-to-run differences, classified as data changes or non-economic metadata
- SEC point-in-time exclusion
- that no WITHHELD original value appears in coverage, summary or the checker's own output

The checker is independent of `scripts/verify_sec_snapshot.py`. It re-derives the hashes with its own code, does not replace that verifier, and does not call it. Run both.

## Usage

```
python3 -I scripts/step23_checker_v2_3.py \
  --new  fundamentals-batch-results_NEW.zip  --new-raw  sec-companyfacts-raw_NEW.zip \
  --base fundamentals-batch-results_BASE.zip --base-raw sec-companyfacts-raw_BASE.zip \
  --expect-date 2026-11-03 \
  --profile scripts/profiles/step23_2026-11-03_pr15_cutover.json     # or: --profile none
  [--new-sha <40 hex>] [--base-sha <40 hex>] [--repo-root <checkout>] [--json-out report.json]
```

Exit codes:

| Code | Meaning |
|---|---|
| 0 | PASS |
| 1 | FAIL |
| 2 | REVIEW |
| 3 | Input error: unsafe, corrupt or missing input, or an invalid profile. Nothing is judged |

Malformed content never passes and never produces a traceback. Each run is first type-checked **on its own** (T0, B0, S1, A6/A8), so identical damage in BASE and NEW cannot pass by agreeing with itself in C1 or D. Safe accessors only prevent crashes; they never turn a wrong type into an accepted value. JSON values of the wrong type (a list or dict where a string is expected, a non-object manifest entry, a non-list gate list, and so on) are checked before use. They are never used as dict keys or set members, and they are reported as FAIL by the check that owns them, e.g. a non-string manifest ticker is FAIL in A6 and A8. As a second line of defence, every check group runs in isolation. An unexpected exception becomes `X0 <group> checks aborted on malformed input` = FAIL, showing the exception type and code location only, never its message or any value. The other groups still run. The WITHHELD targets for the leak self-check are collected before any group runs.

Inputs are ZIP files or extracted directories. ZIP members are read in memory, never extracted. The checker rejects absolute paths, `..`/`.` segments, backslashes, drive paths, NUL, empty segments, duplicate names (including case-insensitive duplicates), symlinks, encrypted members and corrupt archives. Symlinks in a directory input are rejected too.

## Profiles

- `--profile` is required. The default profile was removed on purpose, so the cutover profile can never be applied to later runs by accident.
- A profile binds run-specific expectations to one pair through `applies_to`:
  - evaluation date
  - BASE and NEW `github_run_id`
  - full 40-hex `github_sha`
  - `governance_policy_version`
- **P0** compares these fields with the provenance recorded in both summaries. Any mismatch is FAIL. Profile checks are never skipped silently.
- A malformed profile is an input error: missing `applies_to`, a short SHA, an unknown policy or an unknown `profile_version`.
- The SHA expectation comes from `--new-sha`/`--base-sha`, or else from the profile. A short SHA is never PASS.
- `--profile none` disables only the run-specific numbers and per-ticker expectations: checks B1, B6, C4, D6, D8 and E3, all shown with layer `PROF`. Every structural, governance, coverage, comparison, PIT, integrity and leak check still runs. Without raw inputs or a SHA, the result is REVIEW, never PASS.

## Dependency-map currency (M1)

- The checker carries copies of `DERIVED_DEPENDENCIES` and `GROWTH_DEPENDENCIES` from `src/fundamentals/metric_eligibility_registry.py`.
  - Copied at commit `a1a86d70a9745eb0be1299587b6151d85bf1116d`.
  - File sha256 at that commit: `a1178eba0af6fb3d8d5ed72d10a9cb44945e12d8d1609f34ca129c5008ea335b`.
- **M1** parses the registry in `--repo-root` with `ast`. The module is never imported or executed. The default `--repo-root` is the checkout that contains the script. Possible results:
  - Equal maps: PASS.
  - Any difference: **REVIEW**, naming the entry and the file to update.
  - Missing file, a non-literal map, or no repository: **REVIEW** ("not verifiable").
- The test `test_checker_maps_match_production_registry` makes a production map change fail CI until the checker copy is updated in the same PR.
- Data-level checks fail closed independently: a stale map that disagrees with a governed ticker's `relabelled` lists or `withheld_inputs` is FAIL in B2–B4.

## Checks

| ID | Layer | Rule |
|---|---|---|
| A1 | NEW, BASE | Evaluation date; cutoff = date − 1 in the summary and in every ticker JSON |
| A2 | NEW, BASE | Schema `fundamentals_batch.v2` and a known policy (unknown policy: REVIEW) |
| A3 | NEW, BASE | `operational_review` = PASS |
| A4 | NEW, BASE | `github_sha` = `checkout_head_sha` = `github_workflow_sha` = the expected full SHA |
| A5–A7 | NEW, BASE | Snapshot status and run-time self-verification; manifest file sha256 and `snapshot_content_sha256` recompute. Manifest structure is an independent re-implementation of `sec_snapshot.validate_manifest_structure` (a1a86d7): exact key sets, version, status, `file_count`, `inputs_without_stored_file`, each entry's path (safe relative POSIX), ticker, 10-digit cik, CACHE/FETCHED source, non-negative non-bool size, 64-lowercase-hex sha256, no duplicate paths, sorted by path. On top of that, only a **complete** stored snapshot is accepted: status OK, at least one file, no input without a stored file. An INCOMPLETE run (e.g. `raw_dir=None`) or a NO_SEC_INPUTS run is FAIL. Raw size and sha256 |
| A8 | NEW, BASE | `summary.raw_input` ↔ manifest, 1:1, following the `batch_runner` contract at a1a86d7. **OK**: companyfacts are loaded before the pipeline runs, so `raw_input` (non-null path, sha256, size) and a manifest entry are required. **ERROR**: has `raw_input` only if it failed after the input was loaded, and then it must be in the manifest; an ERROR with neither `raw_input` nor `raw_source` (fetch failed) is the allowed exception. `raw_input` is written before `raw_source`, so an ERROR with a `raw_source` (CACHE/FETCHED) but no `raw_input` is FAIL; a null `raw_source` counts as absent. **EXCLUDED_\***: never fetched, so no `raw_input`, no `raw_source` and no manifest entry. Each side is first validated **on its own**: cik is a 10-digit string, source/`raw_source` is CACHE or FETCHED, sha256 is 64 lowercase hex, size is a non-negative non-bool int, path is a safe relative POSIX path. Identical wrong values on both sides (e.g. cik missing in both) are FAIL. Then duplicate tickers in records or manifest, missing or extra tickers, and path/sha256/size/cik/source mismatches are FAIL |
| S1 | NEW, BASE | `derived_metrics`, `growth` (`components` and aggregate) and `data_sufficiency` are present with status OK for every OK ticker. The orchestrator sets all three unconditionally for every result it returns, so there is no optional case. In B2–B4, a missing stage is FAIL, never "nothing expected" |
| M1 | MAP | Checker maps = production registry (static parse) |
| P0 | PROF | Profile applies to these runs |
| B0 | NEW, BASE | Exact gate structure. With status OK, every ticker has: `withheld`, `scoped`, `not_yet_available` and `no_record`, each a list of names; `unmasked_originals` as an object (`{}` when empty); and `relabelled` with exactly `derived`/`growth`/`data_sufficiency`, each a list of names. A missing or null field is never read as empty. The lists are disjoint and the `unmasked_originals` keys equal `withheld`. Gate status SKIPPED (the production record when no eligibility rows were supplied) is allowed only when the run's policy is `NO_METRIC_ELIGIBILITY_GATE`, and then the record must be exactly `{"status": "SKIPPED", "reason": <non-empty string>}`. Any other non-OK status is FAIL |
| T0 | NEW, BASE | Per-run schema, independent of the other run. Containers and items are objects: normalized metrics, unmasked originals, components, derived, growth components, sufficiency, annual history rows. Every item carries a string `status` (`calculation_status` for sufficiency). The growth aggregate has a string status, and `withheld_components`, if present, is a list of strings. Identity fields have production types: `accession`, `concept`, `filing_date`, `form`, `fp`, `namespace`, `period_end`, `period_start` and `unit` are string or null; `fy` is int or null; `value` is a number or null. **PIT source identity is validated semantically, not just by type.**
- A status-OK observation that is not a composite (a normalized metric, a component or an unmasked original) must have:
  - a real ISO `filing_date` and `period_end` (YYYY-MM-DD, checked by round trip through `date.fromisoformat`, never by comparing strings);
  - a `period_start` that is null or a real ISO date;
  - an SEC `accession` (`##########-##-######`);
  - a finite numeric `value`, under the same contract as production `derived_metrics._is_number()`: an int or float (never bool) whose `float()` is finite. NaN, ±Infinity, and ints beyond the float range (e.g. 10**309) are not valid amounts, because production cannot use them. The check never raises: an OverflowError means "not a valid number" and becomes a direct T0 FAIL, never X0. Leak comparisons keep ints exact, so an extreme original can never abort the run.
- **Composites follow the production contract exactly.** `sec_normalizer.calculate_total_debt()` is the only composite, and it always builds `components` with exactly `current_debt` and `noncurrent_debt`. So:
  - `total_debt` must have an object `components` with exactly those two keys. A missing component, a missing `components` key (even with valid parent identity), an empty object or an extra component are all FAIL.
  - "components" on any other metric is FAIL, because it would exempt an OK value from its own identity checks.
  - The only exception is the gate's WITHHELD mask (status WITHHELD, `eligibility.governance_status` WITHHELD). It replaces the metric, and the original composite is checked in `unmasked_originals`.
  - Every component needs a string status, and an OK component needs valid source identity.
  - An OK composite needs a finite numeric value. Parent-level SEC identity is not required.
- Annual history rows must have a real ISO `filed` and an SEC `accn`. `end` and `start` must be ISO dates when present, and `val` a finite number when present.
- Anywhere in a ticker result, every `filing_date`, `filed`, `period_end` and `period_start` is null or a real ISO date, and every `accession`/`accn` is null or SEC-formatted. These are exactly the values E1/E2 read, so a malformed one fails T0 first. Every `frame`, at any depth, is a string or null. Status values are not restricted. Contract source: production a1a86d7 (`frame` = SEC observation's frame) and every observed artifact (5 batches, 90 result files) |
| X0 | ERR | A check group aborted on malformed input (fail closed; see above) |
| B2–B4 | NEW, BASE | Dependents under the run's policy. **V1**: relabelled = produced dependents; no `set_by`. **V2**: every map entry; marker structure validated on its own (`set_by`, exact `withheld_inputs` in map order, `value` null, `materialized` boolean, false ⇔ `original_status` null, true ⇒ `original_status` string, an absent key ≠ null); then the same-date BASE comparison. BASE V2 markers must carry over; a BASE V1 marker means "produced"; a V1 sufficiency marker without `original_status` limits the comparison to `materialized` and never relaxes NEW's own structure check |
| B5 | NEW, BASE | No WITHHELD status, gate marker or growth `withheld_components` outside governed tickers |
| B7 | NEW | Withheld metrics masked, originals kept, scoped metrics ELIGIBLE, `net_debt`/`debt_to_cash` free of governance markers |
| C1 | NEW, BASE | Coverage = recompute from ticker files: R1/R2, derived, growth components, aggregate, `withheld_component_counts`, sufficiency |
| C2, C3 | CMP | Normalized R1/R2 unchanged; stage coverage identical once governed tickers are excluded |
| D1–D3, D7 | CMP | Same tickers. Ticker-JSON paths classified as RUN_METADATA (`normalized_at`, `fetched_at_utc`, `loaded_at_utc` and similar), FRAME_METADATA_ONLY, FRAME_WITH_IDENTITY_CHANGE (FAIL), GOVERNANCE_MARKER (governed ticker, map item, NEW item is a marker, `status`/`value` unchanged) or DATA_CHANGE (FAIL). `summary.json` changes are allowed only in run metadata, provenance and `raw_input` hashes |
| D4, D5 | INFO | Frame drift with old and new labels; change classes per ticker |
| E1, E2 | PIT | No `filing_date`/`filed` after the cutoff in the results; no post-cutoff accession from raw appears in the results |
| F1 | NEW, BASE | No WITHHELD original in coverage or summary JSON/Markdown. Targets are every amount (`value`-like key) inside each unmasked original, nested ones included (e.g. `stale_observation.value`), of any magnitude including 0 and decimals; `fy` and similar are never targets. Rules: **\|v\| ≥ 1000**: any numeric token anywhere, ±0.5 for rounded display → FAIL. **Smaller values**: exact match only. In JSON, an amount under a value-like key on a path naming the metric or one of its dependents, and not inside another ticker's record → FAIL. The ticker scope is fixed by the outermost object that names a ticker (e.g. a summary record); a nested `"ticker"` field cannot re-scope the amounts below it. The amount can be a JSON number or a string that is exactly that number (`"3"`, `"0"`, `" 3.00 "`); a number embedded in other text (`"about 3 USD"`) is never FAIL-level. any other exact match of a non-zero value → REVIEW. In Markdown, a match on a line naming the metric or a dependent → REVIEW. Zero is matched only in context. Output gives locations only. The report text and JSON are self-scanned (large values anywhere, small values written as an amount) before output |
| B1, B6, C4, D6, D8, E3 | PROF | Profile expectations: exact gate sets, non-governance gaps per stage, derived totals and mix, change classes, raw-changed tickers, named post-cutoff filings |

**Frame rule:** `frame` stays in the comparison and in the snapshot hashes. A frame change is METADATA_ONLY only when the record's other keys are the same and these identity fields are equal: value, `period_start`, `period_end`, `filing_date`, form, accession, concept, unit, namespace, status, fy, fp. A change to null and a removed field are both METADATA_ONLY.

**Stage states:** each stage is read with its own schema. Derived and growth use `status`; sufficiency uses `calculation_status`. A metric missing from a stage is ABSENT, not MISSING (e.g. LLY derived `operating_income_yoy`).

## Limitations

1. In the synthetic fixtures, coverage is generated with the checker's own recompute functions. Agreement with the production coverage code is shown on real artifacts (C1, both runs), not by the unit tests.
2. Profiles are pair-specific. A new pair needs a new profile file, or `--profile none`.
3. The hash checks are internal-consistency checks, as in `verify_sec_snapshot.py`. External authentication of artifacts is out of scope.
4. Small-value leak detection works on exact matches with path or line context. A small original that is re-formatted (rounded, scaled, written in words) is not detected, and a non-zero small value that matches an unrelated number is REVIEW, not FAIL, by design.
5. Checker v2.2 and earlier existed only as working scripts and were never in this repository.
